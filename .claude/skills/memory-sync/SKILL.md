# Memory Sync

## Назначение

Держать `.claude/memory/` (базу знаний проекта — не путать с CLAUDE.md, который описывает правила, а не историю/нюансы) в согласованном состоянии: каждый файл проиндексирован, каждая ссылка в индексе рабочая.

## Когда использовать

- После обнаружения нового факта о проекте, не выводимого из кода (например, инцидент, внешняя зависимость, бизнес-контекст).
- После принятия решения, зафиксированного ADR — memory-документ должен ссылаться на новый ADR (см. skill `new-adr`).
- Периодически — как проверка целостности перед крупным изменением документации.

## Когда НЕ использовать

- Для сиюминутного состояния текущей задачи — используй TodoWrite, не memory.
- Для правил/политик проекта — это `CLAUDE.md`, не memory-документ.
- Для информации, полностью выводимой из чтения кода — memory хранит то, что код не расскажет сам.

## Алгоритм

1. Определить, в какой существующий файл `.claude/memory/*.md` относится новый факт (см. `references/memory-conventions.md`). Новый файл — только если тема реально новая и будет пополняться.
2. Дописать факт в раздел "Принятые решения" — с датой, если это разовое событие (инцидент, конкретное решение).
3. Обновить раздел "Связанные документы", если появилась связь с новым ADR/файлом.
4. Если создан новый файл — добавить его в индекс `MEMORY.md` одной строкой.
5. Запустить `scripts/check-memory-index.sh` из корня репозитория — проверяет, что все файлы проиндексированы и все ссылки в `MEMORY.md` рабочие.
6. Если факт противоречит существующему тексту в `CLAUDE.md` или другом memory-файле — исправить расхождение сразу, не оставлять две версии правды.

## Чеклист

- [ ] Факт записан в наиболее подходящий файл (не создан лишний дубликат-файл).
- [ ] Дата указана, если факт разовый/исторический.
- [ ] `MEMORY.md` содержит ссылку на файл, если он новый.
- [ ] `scripts/check-memory-index.sh` завершился с кодом 0.
- [ ] Нет противоречий с `CLAUDE.md`.

## Ошибки, которых стоит избегать

- Заводить новый файл на каждый мелкий факт вместо дополнения существующего — индекс раздувается, навигация усложняется.
- Копировать в memory то, что уже есть в `CLAUDE.md` дословно — рассинхрон гарантирован при следующем изменении.
- Забыть прогнать `check-memory-index.sh` после ручной правки `MEMORY.md` — опечатка в имени файла ссылки останется незамеченной.

## Лучшие практики

- Обновляй memory в момент, когда факт узнан — не откладывай "на потом", он забудется или потеряет контекст.
- Пиши так, чтобы через год без контекста этой сессии можно было понять, почему факт важен (см. пример инцидента в `security.md`).

## Примеры

`.claude/memory/security.md` — образец записи инцидента; `.claude/memory/deployment.md` — образец фиксации решения с явно помеченным "открытым вопросом на будущее".
