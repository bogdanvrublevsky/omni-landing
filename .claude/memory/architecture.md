# Architecture

## Описание

`main/` — статический сайт anltx, единственная часть монорепозитория, находящаяся в скоупе текущей инфраструктуры. Остальные проекты репозитория (`dlext/`, `ttapp/`, `sgame/`, `treev/`) архитектурно не связаны с сайтом и не описываются здесь.

## Принятые решения

- **Тип:** SSG (static site generation), без бэкенда и без серверного состояния на MVP.
- **Build-инструмент:** Astro. Выбран вместо чистого HTML/CSS/JS ради переиспользуемых компонентов (шапка/футер/меню — один раз, а не дублируются на 2 локали × N страниц) и вместо более тяжёлых фреймворков — потому что не нужен клиентский рантайм для контентного сайта. Компилируется в чистую статику, совместимую с GitHub Pages. Обоснование — `docs/adr/0001-astro-ssg.md`.
- **i18n:** раздельные пути `/en/` и `/ru/` через встроенный Astro i18n routing (не query-параметр, не поддомены). Автоопределение локали по `Accept-Language` при первом визите + ручной переключатель, выбор сохраняется в `localStorage`. Обоснование — `docs/adr/0002-i18n-separate-paths.md`.
- **Контент:** Astro Content Collections (Markdown + frontmatter) для блога и раздела полезностей, вместо ручной вёрстки отдельных HTML-страниц — снижает дублирование и облегчает будущую миграцию на CMS. Подробности — [content.md](content.md), обоснование — `docs/adr/0003-content-collections.md`.
- **Хостинг (MVP):** GitHub Pages, кастомный домен `anltx.xyz`, уже настроен и раньше отдавал dummy-страницу. Подробности деплоя — [deployment.md](deployment.md).
- **Auth / хранилище:** отсутствуют. Появятся при переходе к платной части платформы — это естественная граница между фазой MVP/Beta (статика) и Production/Scaling (требуется бэкенд), см. `docs/roadmap.md`.
- **CMS:** будущая фаза, вне MVP, архитектура не определена. Ограничение: любая структура контента на MVP должна оставаться совместимой с Content Collections как источником данных, чтобы не создавать несовместимость при будущей миграции.
