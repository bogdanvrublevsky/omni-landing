# 0005 — Cloudflare Workers + Telegram для формы лидогенерации

- **Статус:** принято
- **Дата:** 2026-07-21

## Контекст

Сайт продаёт консультационные услуги — нужна форма заявки на консультацию. Хостинг MVP — GitHub Pages, который отдаёт только статику и не может обрабатывать form submit на сервере. Полноценный хостинг с бэкендом сознательно отложен до появления платящих клиентов (см. `docs/roadmap.md`).

## Проблема

Нужен способ принимать и доставлять заявки без выделенного бэкенда, не отступая от текущей "безсерверной" архитектуры и не создавая расходов, пока нет выручки.

## Варианты

1. **Сторонний сервис форм (Formspree, Getform).** Быстро подключается, но данные лида хранятся у третьей стороны, менее гибкий контроль над форматом уведомления.
2. **Google Forms embed.** Минимум усилий, но плохо сочетается с брендированным UX формы на сайте и не даёт мгновенного уведомления в удобном канале.
3. **Serverless-функция (Cloudflare Workers) → Telegram Bot API.** Предложено пользователем ("попробовать с отправкой серверлес функциями в телеграм"). Полный контроль над форматом и доставкой, бесплатный тариф Cloudflare Workers достаточен для MVP-нагрузки, не требует выделенного хостинга — совместимо с текущим статус-кво "хостинг заведём, когда пойдут продажи".
4. **`mailto:` ссылка без формы.** Ноль инфраструктуры, но худший UX и конверсия для лидогенерации — прямо противоречит цели раздела (продажа консультаций).

## Принятое решение

Cloudflare Workers как serverless-обработчик формы, с отправкой уведомления о заявке в Telegram через Bot API. Это первая внешняя зависимость и первый секрет (токен бота) в проекте.

## Последствия

- Токен Telegram-бота — обязательно через `wrangler secret`, никогда в репозитории (см. [security.md](../../.claude/memory/security.md)).
- Появляется новый деплой-таргет отдельно от GitHub Pages (Cloudflare Workers), со своим CI-шагом при внедрении.
- При ошибке Worker необходим видимый пользователю fallback (см. `CLAUDE.md` → Error Handling) — форма не должна тихо проглатывать сбой.

## Уточнение: домен НЕ переносится на Cloudflare nameservers

Worker деплоится на дефолтный адрес `*.workers.dev`; фронтенд обращается к нему через `fetch()` с CORS, без какой-либо привязки домена `anltx.xyz` к Cloudflare. Custom Domain для Worker'а (например, `leads.anltx.xyz`) потребовал бы переноса всей DNS-зоны на Cloudflare nameservers, что означает риск простоя живого прод-домена (нужно вручную воссоздать существующие записи, включая указывающие на GitHub Pages) ради фичи, которая на момент этого решения ещё не реализована. Перенос DNS сознательно отложен — при необходимости брендированного URL или других фич Cloudflare (CDN/WAF) в будущем, это отдельное решение со своим ADR, не часть текущего MVP.
