# MCP Evaluation — anltx (main/)

Оценка необходимости MCP-серверов на момент бутстрапа инфраструктуры (2026-07). Ни один MCP не подключён. Раздел живой — обновляется, когда реально появляется потребность, а не "про запас".

## Рекомендованы к внедрению (по приоритету)

### GitHub MCP

- **Назначение:** программный доступ к PR/issues/checks репозитория `bogdanvrublevsky/anltx.xyz` из сессии Claude Code.
- **Преимущества:** заменяет ручной `gh` CLI, которого на момент оценки нет в PATH этой машины (проверено при попытке узнать видимость репозитория в Stage 2 — команда `gh` не найдена); упрощает работу с PR при переходе от соло-разработки к команде (см. `CLAUDE.md` → Team).
- **Риски:** требует токена с правами на репозиторий — ещё один секрет, который должен храниться вне репозитория (см. `.claude/memory/security.md`).
- **Этап внедрения:** когда реально понадобится работать с PR/issues программно (не только через `git` + веб-интерфейс) — например, при появлении второго участника команды.
- **Приоритет:** средний. Полезен, но не блокирует ничего сейчас — `git`/`Bash` уже покрывают текущий трункованный workflow.

### Cloudflare MCP

- **Назначение:** управление Cloudflare Workers (деплой, secrets, логи) из сессии Claude Code — напрямую относится к `docs/adr/0005-cloudflare-workers-lead-gen.md`.
- **Преимущества:** избавляет от переключения в отдельный терминал/дашборд для `wrangler`-команд; удобно для итеративной разработки Worker'а формы лидогенерации.
- **Риски:** доступ к продовым secrets Cloudflare через MCP — нужно убедиться, что права токена минимальны (только нужный Worker, не весь аккаунт).
- **Этап внедрения:** при фактической реализации формы лидогенерации (Worker пока не существует — см. Stage 3 решение отложить работу над ним до появления Astro-сайта).
- **Приоритет:** средний, привязан к конкретной будущей задаче, не к текущему этапу.

### Browser / Playwright MCP

- **Назначение:** визуальная проверка сайта, автоматизация Lighthouse-подобных прогонов, smoke-тесты критичных путей (форма лидогенерации) прямо из сессии.
- **Преимущества:** `CLAUDE.md` → Testing требует Lighthouse ≥90 как гейт — без браузерной автоматизации эта проверка не может быть частью Claude-driven workflow, только внешний CI-шаг.
- **Риски:** минимальны — локальный инструмент, не хранит секретов.
- **Этап внедрения:** когда появится сам сайт (Astro) — сейчас нечего открывать в браузере.
- **Приоритет:** средний, симметричен появлению Astro-приложения.

## Осознанно не рассматриваются сейчас

- **Filesystem MCP** — избыточен, Claude Code уже имеет нативные файловые инструменты (Read/Write/Edit/Glob/Grep).
- **Docker** — в проекте нет контейнеризованных сервисов (статический сайт + serverless).
- **Supabase / Postgres** — в архитектуре нет базы данных (см. `.claude/memory/architecture.md`) и не появится, пока проект остаётся в фазе MVP/Beta.
- **Notion / Linear / Slack** — нет свидетельств, что команда использует эти инструменты; текущий workflow — git + Telegram (для лидов).
- **OpenAPI** — в проекте нет собственного API.
- **Sentry** — не решено; может стать релевантным для мониторинга ошибок Cloudflare Worker после его запуска, но это не текущая потребность — пересмотреть вместе с Cloudflare MCP, не раньше.
