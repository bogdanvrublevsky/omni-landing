# Plugins Evaluation — anltx (main/)

## Решение: плагин не создаётся

`.claude-plugin/` (упаковка skills/agents/hooks/MCP-конфига в переиспользуемый плагин) нужен, когда конфигурацию Claude Code требуется распространять **за пределы одного репозитория** — на другие проекты или другим командам.

На момент бутстрапа (2026-07):

- Команда — один человек (см. `CLAUDE.md` → Team), рост запланирован, но в рамках **этого же репозитория**, не отдельных проектов с собственным Claude Code окружением.
- Вся инфраструктура (`CLAUDE.md`, `.claude/`, `docs/`) специфична для `main/` и не имеет смысла вне контекста этого сайта — её нечего "переиспользовать" в другом проекте без существенной переработки под другой продукт.
- Остальные проекты монорепозитория (`dlext`, `ttapp`, `sgame`, `treev`, будущие `lwtms`/`sstms`) — вне скоупа (см. `docs/adr/0006-monorepo-scope-boundary.md`); даже если для них позже понадобится своя Claude Code инфраструктура, это не повод упаковывать текущую в плагин — у них другие требования (не сайт, не контент-платформа).

## Когда пересмотреть

Если появится второй репозиторий/проект, которому нужна **та же самая** модель работы (тот же набор hooks/skills/agents, не просто "тоже Claude Code") — тогда имеет смысл извлечь общую часть в плагин. До этого момента — создание `.claude-plugin/` было бы структурой "про запас" без реального потребителя, что прямо запрещено принципами Stage 3 этого бутстрапа.
